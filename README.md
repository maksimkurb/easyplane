# EasyPlane

Control plane for [EasyTier](https://github.com/EasyTier/EasyTier): a new
config server + web panel that speaks the **real EasyTier wire protocol**, so
unmodified `easytier-core` clients (`--config-server`, Android JNI) can connect
and be managed. It is not a fork of `easytier-web`; only the wire protocol is
kept compatible.

Status: **M3 (live status + topology map)** on top of the M2 policy engine.
Real `easytier-core` clients join through invites, receive config after
approval, track desired vs applied revisions, reconnect, go offline/online and
are refused when blocked. Tags, a Tailscale-shaped policy document compiled into
EasyTier ACL chains, MagicDNS names and subnet/exit-node approvals are managed
from the panel, and a denied flow is demonstrably blocked on real clients
(denials, DNS resolution and route approval are exercised against containers
built from the pinned upstream commit). The browser now updates **live** (SSE,
no polling) and a connectivity map shows direct vs relayed peer links, the relay
node, tunnel protocol, RTT, loss and NAT types; the relayed path and the
online/offline stream are proven with three real clients. Hardening (M4) is
next.

## Quick start (Docker)

```bash
cp .env.example .env     # set POSTGRES_PASSWORD, EASYPLANE_ENCRYPTION_KEY,
                         # EASYPLANE_BOOTSTRAP_ADMIN_TOKEN, public URLs, OIDC
docker compose up -d --build
```

Open `http://localhost:8080`, bootstrap the first admin with the token, then
sign in through OIDC. See [docs/DEPLOY.md](docs/DEPLOY.md) for TLS, reverse
proxy and IdP examples.

## Development

Requires Node 22+, [Bun](https://bun.sh) (workspace install only — the runtime
is Node), `protoc` for binding regeneration, Docker for the integration and
conformance suites, and PostgreSQL for local runs.

```bash
bun install
bun run typecheck
bun run test:unit
bun run test:integration      # starts a throwaway Postgres container
bun run test:web

# Server + built UI:
bun run build && bun run web:build
EASYPLANE_DATABASE_URL=postgres://easyplane:easyplane@127.0.0.1:5432/easyplane \
EASYPLANE_ENCRYPTION_KEY=$(openssl rand -base64 32) \
EASYPLANE_BOOTSTRAP_ADMIN_TOKEN=dev-token \
bun run dev

# UI hot reload (proxies /api to 127.0.0.1:8080):
bun run web:dev
```

Schema changes:

```bash
bun run db:generate     # drizzle-kit generate (commit apps/server/drizzle)
bun run db:migrate      # apply manually; the server also migrates on startup
bun run openapi:generate
bun run --cwd apps/web api:generate
```

## Roles

| action | viewer | member | admin |
| --- | --- | --- | --- |
| read networks, devices, invites | ✅ | ✅ | ✅ |
| read audit log | — | — | ✅ |
| create/revoke invites | — | ✅ | ✅ |
| approve/block/delete devices, edit desired config | — | ✅ | ✅ |
| create/delete networks, reveal/rotate secrets | — | — | ✅ |
| read policy, DNS names, routes | ✅ | ✅ | ✅ |
| rename devices, assign tags, request routes | — | ✅ | ✅ |
| edit policy, approve/reject routes, create tags, assign owners, toggle MagicDNS | — | — | ✅ |

All checks are server-side pre-handlers; the UI only hides controls. State
changing requests need the session-bound CSRF token from the `easyplane_csrf`
cookie in `x-csrf-token`.

## Policy, MagicDNS and routes (M2)

- A **policy document** per network (Tailscale-shaped, HuJSON accepted) with
  tags, user groups (expanded through device ownership), device/host/CIDR
  subjects, port lists, allow/deny order, rate limits and an optional
  strict-tag mode. It is validated, versioned append-only, previewable
  ("can A reach B on port P") and compiled **per device** into EasyTier's
  inbound/outbound/forward chains; the compiled ACL is referenced by a
  `policy_version` on each config revision, so it is audited and rollbackable.
- **MagicDNS** is a per-network switch with a zone and unique, renameable DNS
  names per network (enforced in the API and by a DB index).
- **Subnet/exit-node routes** are requested by members, approved by admins, and
  only approved routes reach `proxy_cidrs`/`enable_exit_node`. The panel reports
  what clients actually advertise, including routes it did not approve.
- [docs/POLICY.md](docs/POLICY.md) lists exactly which Tailscale constructs map
  cleanly, which are approximated and which are unsupported — including the
  EasyTier limits that no control plane can work around (DNS zone is a client
  flag, outbound chains default to allow, IP rules are spoofable by a malicious
  peer, a separate local instance cannot be revoked).

## Realtime and the topology map (M3)

- The panel subscribes to `GET /api/events` (server-sent events). The stream is
  authenticated by the same session cookie as the API, role-checked server-side,
  bounded per user (`EASYPLANE_SSE_MAX_PER_USER`) and replayed by
  `Last-Event-ID`; a reconnect the server cannot replay triggers a full cache
  resync. Events cover device online/offline, last seen, approval state,
  applied revision/error, policy/route/network changes and topology updates.
  TanStack Query invalidates or patches the affected caches, so approvals and
  status changes appear without a refresh. [docs/REALTIME.md](docs/REALTIME.md) §1
  explains why SSE and not WebSocket.
- **Topology** is collected with `CollectNetworkInfo` per online device. It is
  adaptive (30 s when idle, 5 s while a map is open, ±20 % jitter, 4 parallel
  probes by default), keeps one bounded snapshot per network and marks cycles
  with failed probes as `partial`.
- The map is `@xyflow/react` with a deterministic radial layout (relay-capable
  node in the centre, one ring per hop, rings grow with node count). Solid green
  edges are direct, dashed amber edges are relayed and name the relay plus the
  first-hop protocol; a violet ring marks relay-capable nodes. A device drawer
  shows the client's raw peer connections and route table, and a per-network
  filter/legend keeps large graphs readable.
- **At least one reachable node matters.** The map distinguishes `reachable`
  (open/static NAT or public-server flag) from `relayCapable` (reachable *or*
  demonstrably relaying for other nodes) and warns when no node is reachable.
  EasyTier relays through any peer both sides can reach, so a NAT-ed node that
  already relays is shown as such — with the evidence, never a bare badge.
- The M3 conformance suite runs three real clients as a hub-and-spoke mesh with
  `disable_p2p` on the leaves; the client itself reports `core-b → core-c` as
  cost 2 via `core-a`, the map matches, ICMP still crosses the relay, and a
  stopped container produces an offline event on a live SSE stream. The
  protobuf bytes of that run are the fixture for the derivation unit tests.

## Security posture (M1/M2)

- OIDC only (authorization code + PKCE, discovery/JWKS, multiple providers).
  No passwords are stored; the break-glass token is constant-time compared and
  disabled once an admin exists unless re-enabled.
- Sessions live in PostgreSQL; only SHA-256 hashes of session tokens are
  stored. Cookies are HttpOnly/SameSite=Lax (Secure outside test/dev).
- Invite tokens are 192-bit random values, stored only as SHA-256; the plaintext
  is shown once. EasyTier network secrets are sealed with AES-256-GCM
  (`EASYPLANE_ENCRYPTION_KEY`) and never appear in revision rows, API responses
  (except an audited admin reveal) or audit logs.
- Unknown config-server tokens are rejected with an RPC error and rate-limited
  per source IP; the session is dropped once over the limit. Pending devices are
  capped per network.
- EasyTier ACL group secrets are never stored: they are derived with
  HMAC-SHA256 from `EASYPLANE_ENCRYPTION_KEY`, a domain string and the network
  id, and only appear in the pushed config.
- Structured JSON logs, cookie/authorization/CSRF redaction, `/health`.
- Known M1–M3 gaps: no UDP config-server transport, no encryption-key rotation,
  no per-organisation isolation (one organisation per deployment), the SSE hub
  and topology snapshots are in-process so the server must run as one replica.
  UDP and horizontal scaling are tracked in M4.

## Tests

```bash
bun run test:unit           # domain rules, crypto, state machine, claims
bun run test:integration    # Postgres + mock OIDC: auth, CSRF, roles, API
bun run test:web            # vitest + testing-library (incl. map/layout/SSE cache)
scripts/build-test-client.sh
docker compose -f docker-compose.test.yml --profile test build
bun run test:conformance    # real easytier-core over ws/wss/tcp + M1/M2/M3 flows
```

The M1 conformance test proves invite → pending → approve → config running →
revision change → rollback → offline/online → block against the real client.
The M2 test (`test/conformance/m2.test.ts`) runs three clients in separate
network namespaces and proves ACL enforcement (200 on an allowed port, timeout
on a denied one, both directions), MagicDNS resolution and route approval
(pending vs approved `proxy_cidrs`, unapproved advertisements flagged,
`enable_exit_node`). The M3 test (`test/conformance/m3.test.ts`) reuses the same
containers as a relay-only mesh (leaves dial only the hub and run `disable_p2p`),
proves the map's direct/relayed edges against the client's own route table,
streams an offline/online transition over SSE, checks SSE auth and the per-user
cap, and pings across the relay while probing. M1 containers use host networking
plus `/dev/net/tun` and `CAP_NET_ADMIN`; M2/M3 use an isolated bridge network
plus a small test-only TCP relay for the config-server connection (some hosts
drop bridge→host traffic). Linux-only; set `EASYPLANE_CONFORMANCE_NO_TUN=1`
when TUN is unavailable.
