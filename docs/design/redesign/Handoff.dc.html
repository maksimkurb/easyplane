Handoff: applying design edits to apps/web
All paths are relative to apps/web/src. Strings: i18n/en.ts and i18n/ru.ts (keep keys in sync, change copy in both).
Rules for a coding agent
  1. Colours, radii, shadows: edit only the CSS variables in index.css (:root light, .dark dark). Canvas ep.css variable names equal the app's, so a token change maps 1:1. Never hard-code hex in components, except the existing status colours (Tailwind amber/emerald/red/violet-500).
  2. shadcn / base-ui components (components/ui/*: button, badge, card, table, input, select, dialog, sheet, tabs-like segmented control, switch, checkbox, alert, empty, skeleton, tooltip, sidebar, dropdown-menu, sonner) keep their API. Change look through class variants (cva) in that file, not per page.
  3. Custom components: components/device-status.tsx (status badges), components/layout/* (shell, brand header), components/shared/* (PageHeader, SectionCard, Field, OptionSelect, ListPlaceholder), components/topology/* (map, drawer), network-/device- cards.
  4. Layout is Tailwind utility classes in TSX; there is no CSS beyond index.css. Responsive: sidebar offcanvas under md, page title 3xl on mobile / 2xl on md+, tables scroll in overflow-x-auto.
  5. Canvas frames are fixed-size mockups, not responsive code: translate spacing and sizes to Tailwind classes; do not copy inline styles.
  6. Keep both themes working and the Russian copy untouched unless the design changes text.
